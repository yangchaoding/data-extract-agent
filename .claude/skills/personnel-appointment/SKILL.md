# 干部任免审批表抽取

用 `extract-agent` 按固定的 schema，把一份或一批干部任免审批表的识别结果变成 JSON。抽取和逐字核对由工具完成；你要做的是把它跑起来、读懂结果、把需要人看的地方准确地告诉用户。

这类表是人事档案，含本人和家属的个人信息。结果只写到用户指定的位置或下面约定的目录；汇报时说结论和需要复核的字段，不要把整张表的内容转述一遍。

## 1. 准备

**输入**：PaddleOCR-VL 的识别结果，一个 JSON / Markdown 文件，或放着这些文件的目录（每页一个 `{文件名}_{页码}_res.json`）。JSON 带页码和坐标，有的话优先用它。

用户给的是 PDF 或图片时，这个 skill 处理不了，要先用 PaddleOCR-VL 识别。不要自己看图把值抄出来：那样的值没有出处，也没有经过核对。

**命令**：依次找，用第一个能用的。

1. PATH 上的 `extract-agent`
2. 当前目录的 `.venv/Scripts/extract-agent.exe`（Linux / macOS 是 `.venv/bin/extract-agent`）
3. 本 skill 目录（`${CLAUDE_SKILL_DIR}`）下有 `local.md` 时，按里面记的本机安装位置

都没有就问用户 extract-agent 装在哪，不要自己安装。

**schema**：当前目录下有 `examples/schemas/personnel_appointment.yaml`（也就是在 extract-agent 仓库里）就用它；否则用本 skill 自带的 `${CLAUDE_SKILL_DIR}/personnel_appointment.yaml`。

**模型接口**：表的全文会发给模型。默认用的是代码里配置的内网服务，但环境变量 `EXTRACT_LLM_BASE_URL` 或 `OPENAI_BASE_URL` 设了的话，会改用它们指向的服务。运行前看一眼这两个变量；指向外部服务时，先向用户确认可以把人事材料发过去。

## 2. 运行

```bash
# 先看切片（不调用模型，几秒钟）：确认读进来的是任免表、内容完整
extract-agent chunks <输入> --show

# 抽取
extract-agent run <输入> --schema <schema> -o <输出>
```

- 一份表大约 1000 token，不会被切开。一次抽取要调 4 次左右模型，实测 2 到 6 分钟不等，取决于模型服务的负载。命令的超时时间给到 10 分钟；批量时放到后台跑。
- 先数清有几份文档：`chunks` 的输出里每份文档有一行 `# <文档名>：N 页…`。同一份表的多页文件（`xxx_0_res.json`、`xxx_1_res.json`）算一份。
- 只有一份文档时 `-o` 必须是文件，它所在的目录要先建好。用户给的是输出目录时，写成 `<目录>/<文档名>.json`；这时把目录直接传给 `-o` 会报 `Permission denied`。
- 有多份文档时 `-o` 是目录（会自动创建），每份写一个 `<文档名>.json`。
- 用户没有指定输出位置时，写到当前目录的 `extract_out/`（在 extract-agent 仓库里它已经被 git 忽略）。
- 结束时标准错误里每份文档有一行 `<文档名>: 通过 N，未通过核对 N，未找到 N`。一份失败不影响其余文档，但退出码是 1。

## 3. 读结果

结果 JSON 里，`data` 是 `{字段: 值}`；`fields` 是每个字段的 `status`、`value`、`evidence`（原文摘抄）、`pages`、`bbox`，列表字段的每一项在 `items` 里各有自己的出处；`summary.needs_review` 是工具认为要人看的字段。`pages` 是从 1 开始的页码。`bbox` 是值所在版面块的坐标，整张表是一个块时它就是整张表的范围，不是单元格。

三种状态在这类表里的含义：

| status | 含义 | 怎么处理 |
|---|---|---|
| `ok` | 值逐字出自原文的这个位置 | 仍要做第 4 节的抽查 |
| `missing` | 没有值，`data` 里是 `null` | 多数是原文这一栏空着，属于正常情况（拟免职务、专业技术职务经常是空的）。`searched` 为 `1/1` 说明全文都看过了，对照切片里那一行确认确实空白即可。只有「姓名」是必填，它缺了才会进 `needs_review` |
| `unverified` | 有值但没通过核对，`issues` 里写着原因 | 对照切片原文，判断是值错了还是摘抄得不够逐字，告诉用户 |

下面这些是 schema 要求的口径，读结果时按同样的标准判断，不要当成错误去改：

- 年月照原文保留（如 `1975.03 (49岁)`），不补日期，不推算年龄。
- 空栏是 `null`；原文明写的"无"保留为字符串 `"无"`；没有家庭成员表时是 `[]`。
- 表里一格分几行写的内容，识别结果读进来之后行与行之间是空格，所以值里可能是空格而不是换行（如 `东岳大学经济学院 经济学专业`）；简历一般会被模型按经历重新分行。空格和换行的出入不是错误，不用报告。

## 4. 抽查

`ok` 只保证值确实写在引用的那一行里，不保证取的是对的那一栏。任免表里好几对字段在同一行，引的是同一段 evidence，取反了程序也查不出来。所以每份表都要抽查下面这几处。`evidence` 是模型摘抄的原文，一般是值所在的那一行，有时带上表头行，太长时中间用省略号略过；值应该是该栏名称后面紧跟的那一格。各版本的表栏目名称略有出入（例如"行政机关任免意见"、"家庭主要成员及重要社会关系"），按意思对应，不要求和字段名一字不差。

- 籍贯 / 出生地
- 全日制教育 / 在职教育，以及各自的毕业院校系及专业
- 现任职务 / 拟任职务 / 拟免职务
- 审批机关意见 / 行政任免机关意见（常常都是"同意"加日期，靠日期区分）
- 本人「姓名」取的不是某个家庭成员的姓名
- 家庭成员的项数等于切片里填了内容的行数，没有把表头或空行算进去

看切片时，有三处是排版痕迹而不是内容：合并单元格的文字会在一行里重复出现；较长的文字在重复处显示为 `〃`；`| --- |` 分隔线可能落在表格中间（工具按普通数据表猜表头，对这种栏目式的表猜不准），它上下的行地位相同。

发现问题时不要直接改结果文件：文件里的每个值都带着程序核对过的出处，手改的值没有。把字段、现在的值、原文对应的那一行告诉用户，由用户决定重跑还是手工更正。用户要你更正时，在汇报里标明哪些值是手工改的。

批量很大、没法逐份抽查时，至少抽查其中几份，并在汇报里说明抽查了哪几份。

## 5. 汇报

说明每份文档的三个计数、需要用户看的字段及原因（`needs_review` 里的、`unverified` 的、抽查发现的）、哪些字段是原文空栏、结果文件在哪。全部正常时一两句话即可。
